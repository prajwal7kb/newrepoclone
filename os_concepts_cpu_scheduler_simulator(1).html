PCB Role in Context Switching

When the OS CPU scheduler switches context from Process A to Process B:

  • The hardware state ($PC, $SP, registers) of Process A is saved directly into Process A's PCB.
  • Process A's state is updated from RUNNING to READY or WAITING.
  • The OS loads Process B's PCB registers into CPU hardware and restores execution.

Multithreading Mapping Models
Many-to-One Model User Threads

Multiple user threads map to 1 kernel thread. Fast context switch, but 1 blocking call halts all threads.

One-to-One Model Linux / Win

Each user thread maps to 1 kernel thread. True multi-core execution; higher overhead creating threads.

Many-to-Many Model Multiplexed

Multiplexes M user threads onto N kernel threads (M ≥ N). Best concurrency without kernel saturation.

OS Concepts Lab Guide & User Manual

Comprehensive overview of topics covered in Modules 1 & 2

Module 1: System Bus & Dual-Mode

• Hardware System Bus: Controls movement of memory read/write data packets across Address Bus (hex locations), Data Bus (payload bytes), and Control Bus (signals).
• Dual-Mode Execution: Protects hardware resources using Mode Bit 1 (User Mode) and Mode Bit 0 (Kernel Mode). Software TRAPs (`int 0x80`) switch privilege securely.

Module 2: Process Management & PCB

• 5-State Machine: Tracks processes through NEW, READY, RUNNING, WAITING, and TERMINATED states.
• PCB (Process Control Block): Data structure in kernel memory storing $PC, $SP, registers, memory limits, and file descriptors during context switching.

Module 2: CPU Scheduling Algorithms

• FCFS: Non-preemptive, executes processes in arrival order.
• SJF / SRTF: Chooses shortest remaining burst time to minimize Average Waiting Time.
• Round Robin: Time-sliced execution via Time Quantum for interactive fairness.
